# P0-01 D5-20：統合NO_GOゲートの異常入力耐性・時点整合強化

実施日：2026-10-29。対象：D5-19統合NO_GOゲートの限定的修正と**36件のオフライン合成回帰テスト**。

**設計・テストのみ。MT4起動・照会・EA/EX4実行・注文・決済・楽天証券への問い合わせはしない。単一口座・単一MT4環境の方針、PHASE-1 BLOCKED、runtime NO_GOを維持する。**

## 1. D5-19からの追加強化

| ID | 発見した曖昧さ | D5-20での取り扱い |
|---|---|---|
| H20-01 | D5-10は過去取引日の構造的に正しいスナップショットも復元可能。D5-19がそれを現時点の整合性として扱う余地 | 結合ゲートで最後の合成停止スナップショットの日付と `expected_day` が一致しない場合、`INTEGRATED_STALE_STOP_RECORD_FAIL_CLOSED` を返す |
| H20-02 | D5-18の合成証拠は**相互間では**時刻が一致していれば整合になるが、D5-19の日次判定の評価時刻と異なっている可能性 | 合成証拠を「統合して整合」と呼ぶ前に、同一の絶対UTC時点であることを確認。不一致なら `INTEGRATED_EVIDENCE_TIME_MISMATCH_NO_GO` |
| H20-03 | 日次判定と証拠の時刻精度が異なる場合、同じ秒への切り捨てによる擬似的一致があり得る | 日次時刻にマイクロ秒が含まれれば厳密な証拠時刻一致を認めない。両者の時間をコード内で取得せず、入力値のみを比較 |
| H20-04 | 単独の正常判定が別ゲートの失敗を隠してしまう危険 | 二重障害・停止ラッチの食い違い・証拠改ざんを組み合わせて、全出力の拒否権限と安全ホールドをテスト |

**注意：** 過去日の記録が正しい可能性と「当該日の現状確認に使用可能」は異なる。古い記録を破棄・書き換えることはせず、結合上の`NO_GO`にする。

## 2. 判定優先度

1. 不正なトップレベル入力、暦日不正、日次日付不一致は `INTEGRATED_INPUT_REJECTED_FAIL_CLOSED`。
2. 子判定の破損、日次評価失敗、停止履歴の破損は `INTEGRATED_COMPONENT_REJECTED_FAIL_CLOSED`。
3. 最新停止履歴の日付が評価対象日と一致しなければ `INTEGRATED_STALE_STOP_RECORD_FAIL_CLOSED`。
4. 日次停止と復元停止に不一致があれば `INTEGRATED_STOP_DISAGREEMENT_FAIL_CLOSED`。
5. 停止・再評価条件が残れば `INTEGRATED_STOP_OR_REVIEW_BLOCKED_NO_GO`。
6. 証拠不足・口座スコープ違い・過去と最新の申告の未照合なら `INTEGRATED_EVIDENCE_BLOCKED_NO_GO`。
7. 合成証拠同士は整合していても日次判定の時刻と一致しなければ `INTEGRATED_EVIDENCE_TIME_MISMATCH_NO_GO`。
8. 全ての**合成入力**が整合しても `INTEGRATED_SYNTHETIC_COHERENT_NEVER_AUTHORIZED`。実行権限は生じない。

新しい状態名は診断用であり、いずれも取引許可ではない。`daily_stop_latched`は合成状態の表現、`safety_hold_latched`は全ケースで真。

## 3. 回帰試験（36件）

- 古い停止記録、停止済み旧記録、未来の停止記録、当日記録の正当な翌日レビュー
- 合成証拠の1秒ずれ・1日ずれ、UTC `Z` と `+00:00` の一致、UTC以外のオフセット拒否、サブ秒の不正な同一視拒否
- 証拠の矛盾、口座スコープ違い、時刻違い、UNKNOWN、重複ID、疑似ブローカー確認、スキーマ違反
- 復元欠落、最小連番の違反、連番飛び、停止解除の履歴矛盾、DD5%停止からの不正遷移
- リスク上限、日次損失とDDの重複、無効な資金入力、不正な暦日/UTC
- トップレベルの余計な許可フィールド、必須入力欠落、入力非改変、連続呼出し間の状態混線防止
- **すべての結果で** `runtime_go_no_go=NO_GO`、`verified_values=null`、`safety_hold_latched=true`、`phase_1=BLOCKED`、許可フラグ群=falseを厳密検査

## 4. 検証の限界

- 実際のMT4口座同一性、建玉・予約注文の有無、EAの装着・稼働、スプレッド、ブローカーとの通信、実ログは未検証。
- 入力は合成データであり、日次時刻・証拠時刻を呼出元が供給する。両時刻が一致しても**真正性、独立性、鮮度、実測事実**を保証しない。
- 停止スナップショットは永続化・外部署名・実口座ID結合が未実装。日付と連番だけでは改ざん・ロールバックを防げない。
- D5-7、D5-8、D5-9、D5-10、D5-18の既存実装は変更しない。D5-19の純粋関数のみ限定的に修正。
- `G1`の4通貨ペア×5属性は未実測のまま。実環境の運用可否は変わらない。
