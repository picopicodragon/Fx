# FINAL-PAPER-99〜103: 手動承認付き・内部仮想通信ラッチ一回限り解除

対象：2026-11-18 の #106→#107（3420秒）という本人申告の正常手動停止 **1件のみ**。
本人は2026-11-18、この事象について追加の安全検証合格を条件とした
**内部仮想売買の通信停止ラッチ解除だけ**を明示承認した。
mainマージ、楽天MT4デモ/実口座注文、AI追加課金、DD4/5や日次損失停止解除は対象外。

## 構造と限界

- 原本ジャーナルを直接書き換えない。承認は既存のjournal SHA256末尾・サイクル数・
  最後のquoteと結び付けた一回限りの別ファイル
  manual_comm_release_20261118.jsonとして保存。既存ファイルがある場合は拒否。
- Python監督が稼働していないことをWindowsで確認し、lockがない場合のみ
  明示スイッチ付きで事前審査を実施。
- ハッシュ鎖全件、履歴#107以降の新しい未申告600秒超のギャップなし、
  直近10件の連続性、仮想建玉/保留シグナル0、他リスクラッチ全てfalse、
  鮮度120秒以内のMT4価格などを検証。
- 許可ファイルの有効期間は作成後300秒以内。再開時の新価格と前回処理価格の
  差は180秒以内。既存journal SHA256が変化したら拒否。
- **新しい価格を実際に処理する1サイクルでのみ**Python内部で通信ラッチ解除し、
  同じ新ジャーナルにrelease SHA256マーカーを残す。次回以降は二度と使わない。
  600秒超の別の停止が発生した場合は再ラッチ、同じ許可で再解除できない。
- AutoTrading OFF。MT4観測EAは読み取り専用のまま。
- 独立したニュースカレンダー/時計認証、費用証明、AI6/6の利用上限は
  **まったく緩めない**。解除後も新規仮想売買の全体判定はNO_GOのまま。
- ローカルpermitのSHA256は改ざん検知用であり、外部署名や本人確認ではない。
  Windows上で本人が明示コマンドを実行することが必要。

## 実機で適用する場合

新PRのLinux/Windowsテスト成功、レビューを確認するまで実機適用を行わない。
稼働中の現行Python監視はそのまま維持し、変更済みコードへの
**自動切り替えは行わない**。新コード用に別Git作業ツリーを用意する。

既存の監視を本人が意図的にCtrl+Cで正常停止した後、
別PowerShellにおいて、その停止済みPythonがないことを確認し、許可ファイルを1度だけ作る。
作業中に既存ロックが残っていたら中止し、削除や再起動をしてはいけない。

    .\scripts\final_paper_stage_manual_comm_release_once.ps1 -Mt4FilesDirectory $mt4Files -ApproveVirtualCommRelease

成功表示 VIRTUAL_COMM_RELEASE_STAGED_NOT_YET_APPLIED_NO_GO は「保留の許可書が作成された」
ことだけを示す。過去の通信停止ラッチはまだtrue。

300秒以内、かつ直近価格間隔180秒以内で安全に再開できる場合のみ、
**同一の承認済み新コードのツリーから**無課金監視を起動する。

    .\scripts\start_final_paper_virtual.ps1 -Mt4FilesDirectory $mt4Files

観測サイクルで manual_comm_release_applied_this_cycle=true が返り、
journalの communication_latched=false と許可ハッシュマーカーの追記が確認できて
初めて解除実施の証拠になる。NO_GOや安全条件不一致なら再試行を重ねない。
ファイルやロックを削除・書き換えない。

> 注意：作業を開始してからラッチが残った場合も、追加のAI呼出しや
> 新規仮想エントリーは認められない。仮想取引開始には別途
> 公式イベント・市場予想の事前保存、独立時刻・取引コスト、
> 3000円/月のAPI費用照合と新たな課金承認が必要。
