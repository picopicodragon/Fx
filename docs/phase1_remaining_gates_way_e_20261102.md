## 3. 方式E：安全な一括オフライン作業（人間の工程ごとの確認不要）
1. **E-GATE-01 / インベントリ**：mainの現行ゲート定義、D537-WP-01〜15、Issue/PR、証拠と受入台帳をクロスチェック。G1〜G9の正式名称・依存・エビデンス・現状を根拠ファイル付きで確定。確認不能ならUNKNOWN/BLOCKED。
2. **E-GATE-02 / 原議差分**：FX-SAF-001〜015、Q109〜Q115の出典レベル、未確定算式、本人決定が必要な箇所を整理。ローカル原本はGitHubへアップロードしない。本人承認を代筆しない。
3. **E-GATE-03 / オフライン検証**：合成固定データによる拒否経路、SQLite隔離テスト、世代フェンス、異常復旧・不明結果の再送禁止、機密漏えい防止のテスト拡充。実OSロック/実停電/実鍵/実MT4の証明を主張しない。
4. **E-GATE-04 / 実証パッケージ**：各実機/独立証拠作業について目的、事前条件、閲覧/収集範囲、実施者、機密取扱、ロールバック、成功/失敗基準、本人承認文面を草稿化。**実行しない**。
5. **E-GATE-05 / 統合確認**：全unit/CI、check_repository、check_traceability、check_acceptance、check_master_spec、check_reconciliation、check_source_evidence、check_source_review_priority、diff/secret checksを実行。PASSは構造・合成範囲のみ。
6. **E-GATE-06 / 最終PR**：作業ブランチからmain宛PRを作成、コミットと未完了証拠の一覧を残す。本人の差分レビューと手動マージを待つ。

順序: E-GATE-01 → 02 → 03/04（並行可）→ 05 → 06。失敗時は安全側で中断・記録、独立して安全な作業のみ継続。既存の仕様・登録項目や承認フラグを根拠なく変更しない。
