# P0-01：全決済失敗・外部注文結果不明時の照合と安全な再試行判断（ドラフト）

> **これは注文実装でも安全実装承認でもない。** Q120の「安全性を確認できた場合のみ条件付き再試行」と、Q195～Q199の「処理結果が不明な間は無確認再送禁止」を同時に満たすため、必要な証拠・保留条件だけを整理した。Q199は本人の個別回答ではなく包括方針による推奨Bの暫定採用。

構造化した資料：`specs/p0_01_closeout_retry_evidence_matrix_draft.json`。P0-01の先行成果である`specs/p0_01_stop_reason_clearance_matrix_draft.json`の独立停止条件も引き続き適用する。

## 1. 「APIが応答した」と「ポジションが決済された」を区別

| 応答種別 | 確認できること | それだけでは確認できないこと |
|---|---|---|
| `RESPONSE_ACCEPTED` | ブローカー/APIが要求を受け付けたとの応答 | 約定量、完全決済、重複注文の不存在、残建玉・SL |
| `RESPONSE_REJECTED` | APIが拒否したとの応答 | 遅延・競合・履歴欠落下での副作用の不存在、最終建玉 |
| `OUTCOME_UNKNOWN` | タイムアウト・通信断・クラッシュ・ログ不整合等により結果不明 | **送信されなかったこと、未約定であること、再送してよいこと** |

Q197/Q198で`PREPARED`、`DISPATCHING`をSQLiteに確定保存していても、ブローカーへの送信・受付・約定を保証しない。特に`DISPATCHING`は送信前クラッシュが起き得るため、**「実際には送っていないはず」という推測だけで自動再送しない**。

## 2. 再試行の検討より先に揃える必要がある証拠

1. **同一操作の識別：** Q195の論理処理ID、試行ID、口座・通貨ペア・残建玉識別子の対応が一意。新しいUUIDv4の発行（Q196）は再試行許可ではない。
2. **ブローカー側の独立照合：** 注文・約定/出来高・保留中注文・ポジション・残数量・サーバー側SL・関連履歴を、直前の試行と突合。
3. **二重決済・反対売買の否定：** 前の注文が遅れて約定する可能性、部分約定・未処理注文・逆方向の残建玉等がなく、必要な追加決済量を正確に特定できる。
4. **耐障害ログの整合：** SQLite側の確定済み処理意図・送信直前状態・応答分類と、ブローカー状態の時系列を再構成できる。再起動、ログ欠落、DB不整合、時計や価格の異常時はFail Closed。
5. **依存停止理由の保持：** Q121の日次・DD4/5・通信・隔離失敗・注文不明などの停止理由を独立保持する。Q171の隔離失敗は人間承認が必要であり、安全な通信回復だけで解除しない。
6. **別途承認される再試行規則：** 上記が揃っても、最大回数、間隔、ブローカー固有の応答、マーケット休場時、対象ポジション、データの鮮度、履歴の遅延、並行処理排他、本人への重大通知と介入を実装前に確定する。

上記の証拠が**1件でも不足・矛盾**していれば、`BLOCKED_UNKNOWN`として新規注文・自動決済再試行を止め、重大通知と人間の介入に移行する。既存建玉の安全な管理とサーバー側SL確認は可能な範囲で継続するが、通信断やPC停止中はローカルの安全管理を保証できない。**停止を守ることと、リスクが消滅したことは別**である。

## 3. 仮判定の4分類

| 判定 | 説明 | 自動決済再試行 |
|---|---|---|
| `BLOCKED_UNKNOWN` | ブローカー/建玉/約定/履歴・副作用の結果が不明 | **禁止** |
| `BLOCKED_NOT_NEEDED` | 全決済完了・残建玉なしを独立照合済み | **不要、禁止** |
| `ELIGIBLE_FOR_LATER_POLICY_CHECK` | 必要残量が存在し、重複/反転の危険が否定できたという**仮定** | **このドラフトでは禁止**。正式に承認された個別再試行方針の確認が別途必要 |
| `BLOCKED_OTHER_STOP` | 隔離失敗・未知状態等、前提の安全検証が不成立 | **禁止** |

重要：`ELIGIBLE_FOR_LATER_POLICY_CHECK`は**「発注可能」ではない**。再試行を検討するための証拠要件が揃った場合の分類にすぎず、実際の再送を許可するアルゴリズム・トリガーは未策定である。

## 4. 合成データによる確認項目（12例）

受理応答だけで決済完了と誤認する例、拒否応答だけで未実行と誤認する例、`DISPATCHING`後のクラッシュ、部分約定、遅延約定、結果不明、別プロセス・手動操作の競合、完全決済済みの再送、Q171隔離失敗、DD5%本人承認ラッチを含む。

各ケースに期待するのは**拒否・追加照合・将来の方針検討まで**であり、本番発注・デモ口座操作・MT4操作は行わない。これらの期待値は実注文コードの動作を試験した結果ではない。

## 5. P0未決事項

MT4/ブローカーの一意な注文・約定・残建玉の照会仕様と履歴遅延、部分約定/再クオート/約定拒否、二重送信防止、決済再試行の最大回数/間隔、通信や市場休場時、外部での手動取引、SQLiteとブローカー間の非原子的性質、ログ破損と復元、重大通知と人間介入・解除記録の具体化が必要。

原本の逐語照合が完了したのはQ116～Q122の対象範囲に限定される。Q195～Q199の原議エクスポートとの逐語再照合は本資料では実施していない。

**安全状態は不変：** `implementation_approved=false`、`human_safety_approval=false`、`owner_approved_for_safety=false`、`forward_trading_enabled=false`、PHASE-1 BLOCKED。本資料の一部を採用しても、実装や実売買承認を意味しない。
