# P0-01：口座・注文・価格・入出金データの整合性とリスク審査ゲート（ドラフト）

> **仕様照合とデータ契約の未承認草案。発注アルゴリズム／日次損失計算器／DD計算器ではない。**
>
> Q116～Q119の原議引用7/7 EXACT、Q117/118の未割当文脈ヒント2件の本人MATCH、および現行の`specs/safety_foundation.md`を参照する。原本の全文はGitHubに登録しない。例外時の正確な数値算式と復旧方法は今後の本人承認が必要。

機械可読の監査台帳：`specs/p0_01_risk_data_consistency_draft.json`。Q120～Q199の注文結果不明・再送禁止とQ121の独立停止理由は別の安全ゲートとして併用する。

## 1. 3つの計算基準を混同しない

| 対象 | 採用された計算方針 | 典型的な不整合・未決事項 |
|---|---|---|
| **発注前の1件0.5%/総額1.0%（Q116）** | 発注審査時の口座純資産を基準に、既存建玉・未約定注文・新規候補のSL基準想定損失を**円換算して合算**。超過・算定不能なら新規拒否 | 純資産と残建玉/未約定/気配値の観測時点、通貨換算、部分約定、発注競合、最低ロット、スプレッド・手数料、SLの有効性 |
| **日次損失額と上限1.5%（Q117/118）** | NY17:00を起点とした**外部入出金補正済み純資産の正味変化**を主計算。独立した費用・損益集計で照合。上限額は**当該NY17:00開始時点の純資産×1.5%**で取引日中固定 | 入出金効力日、遅延記帳/訂正、開始スナップショット欠落、NY夏冬時間、利益相殺、スワップ/費用二重計上 |
| **累積DD 2/3/4/5%（Q119）** | 外部入出金に応じて仮想口数を調整する**単位当たり純資産**の高水位方式。資金移動を運用リターンと混同しない | 初期口数・単価、入出金での発行/償却・高水位更新、残高ゼロ/マイナス、再起動復元、遅延評価・端数・時計 |

これらは同じ「equity」を使っていても**異なる測定目的**を持つ。たとえば日次入金によって当日の1.5%上限額を引き上げる処理はQ118に反する。DDの元データの単なる時点差を「運用損失」または「復旧」と判定してはならない。

## 2. 一緒に確認すべき9種類のデータ

| ID | 対象 | 代表的な検証 |
|---|---|---|
| DS-01 | 現在口座純資産 | 口座ID・通貨、観測時刻、残建玉/価格との一貫性 |
| DS-02 | 既存ポジション | すべてのポジションID・数量・方向・SL、部分約定 |
| DS-03 | 未約定・送信中注文 | ブローカーの注文一覧とローカルのDISPATCHING等、重複リスク |
| DS-04 | FX価格と円換算 | シンボル、bid/ask、ティック/ピップ価値、換算経路、スプレッド |
| DS-05 | NY17:00開始純資産 | 固定された取引日基準額、DST、スナップショットの永続化 |
| DS-06 | 外部入出金台帳 | 資金移動の分類、基準時刻、後日訂正、内部振替との区別 |
| DS-07 | 損益・手数料等の独立照合 | 実現/含み損益、スワップ・手数料の二重計上防止 |
| DS-08 | DD仮想口数・高水位 | 口数推移、入出金時単価、高水位、再起動復元 |

**鮮度・取得時点に関する注意：** Q128で採用した**15秒**はDD2/3監視解除用データの鮮度上限である。新規発注の価格、換算値、口座純資産、NY17:00起点スナップショットへ**一律に15秒を流用してはならない**。データ領域ごとの具体的な許容時差は今後の承認事項である。

## 3. 不整合時の安全側判定（実装仕様の承認ではない）

- **発注前リスクを算定できない／上限超過なら新規注文を拒否**。不足した未約定注文をゼロと見なして合計しない。最小ロットへ切り上げて上限超過になるなら見送る。
- **NY17:00開始額が不明、入出金時刻が競合、独立損益照合に不一致**なら、正常な日次リスク状態として新規発注を許可しない。事後の基準額再構成手順は未決。
- **DD仮想口数の履歴破損や高水位復元失敗、停止理由の永続記録欠落**なら、安全側状態を維持。DD4/5の本人明示承認停止を勝手に解除しない。
- **売買結果不明な注文や未処理注文**はQ120/Q195～Q199に従いブローカー実態の独立照合が必要。今回の数値データ整合が成功しても、注文状態不明の停止を解除しない。
- **スリッページやギャップ損失**はSL価格の最大見積だけでは保証できない。0.5/1.0%は計画時の審査上限であり、実損失上限の保証ではない。

## 4. 合成監査シナリオ16件

`DC-01`～`DC-16`は、口座純資産の時点ずれ、未約定注文欠落、通貨換算不能、ロット制約、NY17:00開始値不在、入出金の境界競合、スワップ重複計上、DD口数復元失敗、再起動後の停止フラグ不明、DD4/5承認欠落等を想定。

`READY_FOR_FUTURE_FORMULA_REVIEW`を含めて、**全16件とも新規注文許可はfalse**。これはこのドラフトに発注コードや正式な再開権限がないためであり、将来の仕様として「あらゆる正常データでも注文を永久禁止」と決定するものではない。今後は数値計算例、限界値、時系列・DSTの境界、取引所/ブローカーの実態、故障注入テストへ展開する。

## 5. 次に必要な決定

1. データ領域ごとの観測時刻・受信時刻・有効期限、および複数ソース間の整合条件。
2. 口座・残建玉・未約定注文・DISPATCHING中の処理を、一貫した発注前リスク審査に結びつける競合制御。
3. SL損失・手数料・スプレッド・クロス通貨の円換算と端数処理、最低ロット等。
4. NY17:00開始純資産・外部入出金・損益内訳の保存・照合と欠測時の復旧方針。
5. 仮想口数と高水位の初期化、口数調整、入出金例外・残高異常・再起動復元。

**承認と稼働は不変。** `implementation_approved=false`、`human_safety_approval=false`、`owner_approved_for_safety=false`、`forward_trading_enabled=false`、PHASE-1 BLOCKED。本人の安全仕様承認とMT4等での検証を経るまでは、口座接続・本番注文は行わない。
