# FWD-489〜600：全研究証拠を単一コマンドへ統合する非発注フォワード準備フェーズ

## 目的と開発の高速化
複数の細分PRとWindowsごとの手動テストをやめ、BLS予定原本、公式ニュース、米欧日イベント、発表前予想、MT4観測、価格・AI研究を**同一PR内の3つの研究モジュールと回帰テスト**でまとめて実装。リポジトリ規約でmainへの最終マージは本人のみ。コードは研究専用でデモ/本番取引は一切許可しない。

## 新しいモジュール

### 1. research.forward_consensus_archive_batch
- 最大64個の発表前予想アーカイブを再検証。既存forward_macro_pre_release_capture.verify_archiveの署名SHA・テキスト・取得前後日時・ペア/単位を厳密に継承。
- BLS実原本バンドルのbls.ics、calendar.json、snapshot.jsonを再検証し、完全一致するICS SHA256＋イベント名＋UTC時刻のレコードだけ数える。
- 旧版カレンダーへの紐付け、イベント未一致は自動補完せず保留。重複同一イベント/ペアと破損記録はFail Closed。
- 1つのイベントに複数ペアの予想があっても「全ペアが網羅された」と宣言しない。出典本人確認や取得時刻の独立認証、イベントの完全性は未達。
- 予想アーカイブがない場合、明示的な欠落カウントと次の収集課題を返す。ファイル出力・ネットワーク・AI APIは0。

### 2. research.forward_mt4_long_run_review
- 既存forward_mt4_multisession_reliabilityを再利用して、デモMT4観測器から利用者がコピーした3通貨ペアCSV（1セッション最大30周期）とオプションログを検査。
- 通信・時刻・30周期上限の証拠、失敗記録、セッション間の重複/衝突を既存監査で評価。NY17をIANA DSTで扱い、観測のあった取引日バケット数を数える。
- 2回以上、2バケット以上の観測とログ証拠がない場合は明示保留。30周期停止マーカーが全部そろっても取引安全やデモ口座の真正性が証明されたとはみなさない。
- 既存のMT4/EAの起動・設定変更・通信・注文は**一切行わない**。ファイルが無ければ「未取得」扱い。

### 3. research.forward_fullstack_noorder_hub
次の**一つのCLI**で既存のすべての証拠を横断確認：

    python -m research.forward_fullstack_noorder_hub

追加指定できる引数（いずれも任意、同時指定可能）：

- --bls-snapshot-dir 保存済みBLS二形式原本フォルダー
- --official-news-bundle 保存済みBLS/FRB/ECB/日銀ニュースRSSバンドル
- --external-macro-file USD/EUR/JPYの時点付きイベント・発表前予想JSON
- --forecast-archive 既存書込み一回の事前予想アーカイブ（最大64個まで繰り返し）
- --session LABEL=DIR コピー済みMT4デモ観測器CSVフォルダー（最大24セッションまで繰り返し）
- --experts LABEL=TXT、--compile LABEL=TXT 監査用ログ（セッションに対応）
- --observation-store 既存研究イベントのハッシュチェーンジャーナル
- --ai-ledger 既存AI研究API判定ジャーナル（最大24個）
- --asof-utc yyyy-MM-ddTHH:mm:ssZ（省略すると実行時Windows時計UTC、独立認証なし）
- --out 新規JSONレポートの出力先（省略すると画面出力だけ、既存ファイル上書き不可）

全入力なしでも `NO_GO` と必要な証拠/未取得箇所を出力。入力がある場合はその原本の完全性を再検証し、相互の不一致をまとめる。価格・AI研究の全体キャンペーンはMT4セッションが1件以上ある時だけ起動し、仮の114 CSVや架空セッションを捏造しない。
独立ソースの認証、予定全網羅、予想の意味的妥当性、MT4口座と注文停止の安全性、本人承認などは未達のまま表示。

## Windowsでの最小手動作業
現時点で利用者が持っている `$originalBundle` は2026-11-13のBLS実原本の絶対パス。最新PRブランチを **別worktree** で取得後、次の一行を実行するだけで、既存原本を使った広範な研究準備判定が可能。

    python -m research.forward_fullstack_noorder_hub --bls-snapshot-dir $originalBundle

保存済み公式ニュース原本やMT4観測セッションがある場合は、コマンドのオプションで同時に指定できる。**存在しないデータを無理に用意して実行する必要はない。**
完全オフライン、バックグラウンド実行なし。原本を更新しない。`--out` を省略すればレポートも保存しない。

## 残る重要なハードブロッカー
- 実FXの主要指標を米欧日で網羅する独立予定カレンダー、発表前の市場コンセンサスの時点付き原本。
- MT4デモ口座の本人確認・サーバー時計照合・EA発注不可の独立検証。
- 経済イベント前後15分の停止と再開の実動作、単一0.5%、全体1.0%、日次1.5%、DD4〜5%の監査。
- 実運用・デモ注文には別途明示承認。未承認状態では現地システムに接続しない。

## 守るべき安全境界
`runtime_go_no_go=NO_GO`、`safety_hold_latched=true`、`demo_orders_permitted=false`、`real_orders_permitted=false`。ネットワーク0、AI API0、MT4/EA操作0、実/デモ注文0。
未来の成果や収益、発表スケジュール完全性を主張しない。自動マージなし。テスト完了は実資料の真正性確認・正式受入を意味しない。
