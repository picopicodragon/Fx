# RISK-3P-115〜120：合成リスク引継ぎの不正型・不審な比較処理からの防御

2026-11-06 JST。PR #193がmainにマージ済みとGitHubで確認後、方式Eの新ブランチで開発。

## 背景と問題

従来の`review_synthetic_loss_handoff`では、二つの架空計算結果をデータクラスで受け取るとき、**その型がデータクラス本体であること**は検査していたが、各フィールドの型は完全に検査できていなかった。Pythonの`dataclass(frozen=True)`は代入による変更を制限するだけで、作成時に属性に任意オブジェクトを設定できる。悪意ある`__eq__`を持つオブジェクトを`reason`、quote属性、通貨脚に入れると、結果比較・タプル比較で不要なコードが実行されたり例外が表面化したりする可能性がある。

今回、**合成モックの照合関数だけ**を改良する。任意コードの隔離サンドボックス実装や、外部データの完全な真偽検査を目的としない。

| 工程 | 実装・検証 |
|---|---|
| RISK-3P-115 | 二つの架空結果`Review`の全フィールドを、単純なstr/bool/None/文字列ペアのtupleだけで構成するか事前検査。型偽装、深い配列、128件超の配列、極端な長文字列を拒否 |
| RISK-3P-116 | 架空の価格、契約、チケット、取引の各データクラスの値を比較前に型検査。文字列でないID/価格などの不審値は比較しない。数量・損失数値の不正は従来の数値解析不可エラーで拒否 |
| RISK-3P-117 | 元の合成計算器の再実行中に予期しないPython例外が起きても、プライベートな入力・例外文を含まない**固定コード`P103_MOCK_RECOMPUTATION_EXCEPTION`**でFail Closed |
| RISK-3P-118 | 故意に例外を送出する`__eq__`オブジェクトを架空レポートと価格・IDに挿入しても、比較処理を呼び出さず、安全に拒否できることを検査 |
| RISK-3P-119 | 成功する架空の3チケット引継ぎは維持しつつ、異常な項目、型、128件超、未知の照合フラグ、偽売買許可を検出。常にNO_GO/停止ラッチtrue |
| RISK-3P-120 | 31件の回帰テスト追加、Q109で既存の合成ソースに紐付け、RISK-3P-02の固定テストリスト更新、Windows/Repository CI、PR |

## 範囲と安全な限界

オフラインの合成データクラスは汎用の不正Pythonコード実行環境を安全に隔離できるわけではない。今回のチェックは、**明示的なデータ構造と値の比較を危険なカスタムオブジェクトに適用しないための防御**であり、すべての任意オブジェクトからの副作用完全防止を保証しない。例外によるFail Closedも、外部システムの停止を保証するものではない。

成功値`mock_binding_consistent=True`は同一の架空スナップショット内部での損失引継ぎの整合性だけを示す。**ブローカー出典、実ストップ執行、証拠金、本人承認、実注文の安全性を証明しない。**

入力件数128、架空の3ペア USD/JPY・EUR/JPY・EUR/USD、ポートフォリオ256桁、損切り96桁の従来設定を維持する。Q109の45オフラインソースも追加しない。

**P05 0/8 BLOCKED、G1実証0/15、FX-SAF原議0/15、FORM承認0/43、PHASE-1 BLOCKED、runtime NO_GO、safety_hold_latched=true、verified_values=null**を維持する。0.5%／1.0%／日次1.5%、DD4%新規停止／DD5%全決済と人間承認、NY17:00、通信障害・時計異常、単一デモ口座、既存EAの無干渉なども変更していない。

楽天MT4、EA、実建玉、未約定注文、秘密値、私有Windowsログにはアクセスしない。方式EによりオフラインのPR・CIまで連続作業を進めるが、mainへのマージや停止解除・実売買承認は行わない。
