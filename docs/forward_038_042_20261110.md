# FX-FWD-038〜042：連続観測証拠の完全チェーン監査とWindows引渡し

## 背景と実装
これまでの単一レシート検証では「最後のレシートが正しい」ことは検査できても、途中の欠落・順序の変更やリセットを全履歴から確認できなかった。今回の5工程は**完全な過去の受領ファイルを先頭から並べて**検証する。

| 工程 | 実装 | 限界 |
|---|---|---|
| FWD-038 | `research.forward_receipt_chain.verify_chain` で連番、ハッシュ、前回レシート参照、時刻増加、重複IDを検査 | 自己申告のローカル証拠 |
| FWD-039 | 指定された連続周期の5分超ギャップを監査し、NO_GO固定 | 元々記録されなかった履歴の完全性は証明しない |
| FWD-040 | `research.forward_receipt_manifest` でレシートをSHA-256固定して監査マニフェストを生成 | 外部時刻・市場情報の認証ではない |
| FWD-041 | 欠落、途中削除、改ざん、重複、順序逆転、ギャップの単体テスト | MT4実機の通信遮断や長時間稼働試験ではない |
| FWD-042 | `scripts/forward_receipt_chain_once.ps1` でWindowsの手動一回実行をまとめる | ユーザーPC上のPowerShell実機実行、タスク登録は未実施 |

## Windows手順（手動、研究用）
以下の`cycle001.json`、`cycle002.json`は**既存のFWD-028レシートファイル**のファイル名例。新たな口座やMT4端末の接続を要求せず、適切な元ファイルが無ければ中止する。

```powershell
.\scripts\forward_receipt_chain_once.ps1 `
  -ReceiptsDir out `
  -ReceiptFiles @("cycle001.json", "cycle002.json") `
  -ManifestOutput out/forward_receipt_manifest_001.json `
  -AuditOutput out/forward_receipt_audit_001.json
```

安全確認では、1から始まる連続したレシート番号と前回SHAが一致することを要求する。既存ファイルの上書きはしない。**5分超の周期ギャップが存在しても監査レポートは生成されるが、実運用の再開は認めない**。本モジュールはもともと常時NO_GOであり、ギャップ後のポジションや取引再開には一切接続しない。
