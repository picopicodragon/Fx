# RISK-3P-133〜138：合成リスク算術の丸め検出とFail Closed

作成日：2026-11-06 JST。PR #197のmainマージを確認した後、方式Eの新規ブランチで実装。

## 発見した防御上の不足

前工程では、架空ポートフォリオ計算のDecimal精度を256桁、架空ストップ損失とJPY換算の精度を96桁へ引き上げ、独立したDecimalコンテキストを使っていた。ただし、計算途中でDecimalが有効桁数を落とす**丸め（`Rounded`）**や実際の精度喪失（`Inexact`）を生じたかどうかを、計算完了時にチェックしていなかった。

今回の上限内の架空入力では通常256／96桁で足りるが、将来の入力範囲変更や数値演算式の追加で桁数が増えたとき、プログラムが**計算精度の不足を暗黙に受容しない**ことを目的とする。

## 工程

| 工程 | 改善・検証 |
|---|---|
| RISK-3P-133 | `phase1_three_pair_synthetic_risk.py`の256桁Decimal局所コンテキストの演算フラグ`Inexact`・`Rounded`をチェック。発生時は`SYNTHETIC_ARITHMETIC_ROUNDED_FAIL_CLOSED`で拒否 |
| RISK-3P-134 | `phase1_three_pair_synthetic_stop_conversion.py`の96桁合成ストップ算術にも同じ拒否を追加 |
| RISK-3P-135 | 候補500円・総計1000円の境界付近の微小端数、巨大な3因子JPY換算で精度不足を再現。丸めて小さくした結果を出力しない |
| RISK-3P-136 | `Rounded=True`かつ`Inexact=False`となる**ゼロ桁の切捨て**も検出。精度上限の変化を、リスク数値として黙認しない |
| RISK-3P-137 | 不完全な演算は損失額・通貨脚・各チケット結果を返さず、`BLOCKED`、`NO_GO`、停止ラッチ有効を維持。正常な精度での厳密計算、未照合時の拒否も回帰 |
| RISK-3P-138 | 新規22件のオフライン単体テスト、既存2ソースへのQ109追跡、RISK-3P-02の固定テスト対応追加、PRおよびCI確認 |

## 実装上の注意

**演算フラグは独立したDecimalコンテキスト内で検査する。** 呼出元のグローバルな丸め設定・指数範囲・例外トラップに依存しない。新テストでは、モック実装に対して**低精度コンテキストを注入**し、実際に丸めが起きた場合の結果を観察する。これは実運用精度を変更する操作ではない。

丸めが発生した場合、外部へ公開する最終結果は損失額・正味/総通貨脚を含まない拒否オブジェクトとする。精度が下がっても丸めのない簡単な架空計算は算術完了としてよいが、**どちらの場合も売買は禁止**する。

この検査はPython Decimalの数値演算に対する限定的なFail Closedであり、ブローカーの契約サイズ、約定、ギャップ／スリッページ、手数料、口座情報の真正性、最大損失の実証ではない。過去の4取引ペア指定と現在の3ペアG1合成検証も混同しない。
