## 1. 対象・背景

既存環境Aは楽天MT4のデモ口座、画面の銘柄名は`USDJPY`/`EURJPY`/`GBPUSD`/`AUDUSD`。
本人報告により、`MACD Sample`がナビゲーターとチャートの両方に存在し、`AutoTrading=OFF_LIKE`、既存の**保有建玉または未約定注文あり**、接続表示`CONNECTED_LIKE`、ローカルログ取扱い`ACKNOWLEDGED`。

EAが実際に既存注文を発したかは不明であり、これらの操作・注文を**一切変更しない**。新しい読取プローブは環境Aに設置しない。

## 2. 公式根拠と確認が必要な点

### 楽天証券：デモ口座

公式「楽天MT4デモ口座開設」は、楽天FX口座の開設が前提、デモ口座は**何度でも作成可能**、レバレッジは25倍、**初期デモ証拠金500万円固定・入出金不可**と説明している。
[楽天証券 楽天MT4デモ口座開設](https://www.rakuten-sec.co.jp/web/fx/mt4/demo-account.html)

**重要な保留：**「何度でも作成可能」は「**同時に複数の独立したデモ口座を保持可能**」を意味すると断定できない。新規作成が既存デモ口座を無効化・入替するか、個人の同時保有数制限と同時ログイン可否は当該公開ページに未記載。既存注文があるため、**確認なしに追加口座申込みボタンを押さない**。

楽天証券には、別の楽天FXデモ取引ページで「利用者1人につき1口座」というFAQもあるが、**FX一般デモのFAQを楽天MT4デモの運用規則と同一視しない**。[別商品FAQ](https://rfx.rakuten-sec.co.jp/demo/faq/)。

楽天MT4専用の端末ではデモ口座ログインサーバーは`RakutenSecurities-Demo`、本番は`RakutenSecurities-Live`。楽天の公式手順ではMT4インストーラーは**インストール後に自動起動**する。したがって承認前にインストーラーを試しに起動しない。
[楽天証券 ダウンロードとログイン](https://www.rakuten-sec.co.jp/web/fx/mt4/download/)

### MetaQuotes：MT4インストール分離

MetaQuotes公式によれば、複数のMT4端末を同時に使うには**異なるインストールディレクトリ**へ別々にインストールする必要がある。各端末には通常、端末のインストール先に基づく**異なるデータフォルダー**が生成される。
[MT4 インストール](https://www.metatrader4.com/en/trading-platform/help/userguide/installation)
[MT4 データフォルダー構造](https://www.metatrader4.com/ja/trading-platform/help/userguide/start_comm)

実際のデータフォルダーは各端末で「ファイル → データフォルダーを開く」により検証する。**インストール先が異なるだけでは十分ではなく、データフォルダーとログ領域の差異を確認する**。

設計初期は**Windows標準の通常モード**を使用し`/portable`モードをデフォルト採用しない。WindowsのUAC無効化や管理者権限の常時使用を分離目的で要求しない。インストーラーの保存先選択可否は別途確認する。

## 3. 推奨アーキテクチャ（成立条件付き）

```text
現行デモ環境A（手を触れない）
  既存ログイン / Rakuten MT4 install A / MT4 data A
  MACD Sample attached / positions-or-pending-orders YES
                      X 口座・データ・EA・ログの流用なし X
検証用デモ環境B（新規設置未承認）
  *別の* 独立した楽天MT4デモ口座（ブローカー許可を確認）
  *別の* MT4 install B と data B と Experts/Journal logs B
  Broker server: RakutenSecurities-Demo only
  No attached EAs / no open or pending orders
  Four exact MT4 symbols in Market Watch
  P0-01 MQ4/EX4 not installed; no terminal execution until separate approval
```

**独立とは**単なる別チャート・別プロファイルではなく、少なくとも以下の分離を意味する。
- **口座IDの区別**は本人がローカルで確認し、数値はGitHubやChatGPTへ送らない。既存AのIDとBのIDが異なることだけ判定する。Bの建玉・保留注文がゼロ。
- **MT4本体の別インストールディレクトリ**を確認する。既存Aのセットアップ/設定を上書きしない。楽天版インストーラーの選択可能性は未確認なので実作業前に再調査/承認する。
- **データフォルダーA/Bの不一致**を「ファイル → データフォルダーを開く」で各端末の内部で確認し、別々の`MQL4/Experts`・`MQL4/Scripts`・`MQL4/Logs`とジャーナル管理を維持する。個人の絶対パスは共有不要。
- **VPS、コピー取引、EA自動インストール、自動EA起動、DLL/WebRequest**などの設定を無断で有効化しない。仮にデモ環境Bを使っても、自動売買OFF表示をスクリプト起動防止の保証としない。
- **ライブ口座`RakutenSecurities-Live`への接続は拒否**。デモ環境Bには別のログインID/資格情報を本人だけが保存し、コード、Git、チャット、ログに含めない。本人既存Aの保存パスワードをコピーしない。

## 4. 検証用デモの500万円と本番10万円の乖離

楽天MT4デモの初期資金は500万円固定で、本番想定10万円の50倍となる。デモ口座の`equity`をそのまま資金管理に渡せば、予定リスク（1取引0.5%＝500円、総リスク1%＝1,000円、日次1.5%＝1,500円）が不適切に50倍相当へ拡大する恐れがある。デモ環境Bでは**一切注文を出さない**ことを維持し、将来のリスク計算テストはMT4口座エクイティと混同しない**完全オフラインの10万円仮想純資産**に限定する。デモでの約定テストを始める場合は別仕様・別承認が必要。

`MODE_TICKVALUE`は口座通貨建て評価と銘柄契約仕様の独立検証が必要。`FORM-01`/`FORM-03`は未承認。
