# P0-01 D5-17：単一MT4環境における口座識別と報告の照合設計

作成日：2026-10-29。依存：D5-15単一環境方針（PR #130）、D5-16未実施プレフライト（PR #131）。

**工程区分：OFFLINE_DOCUMENT_DESIGN_ONLY。最終判定：PHASE-1 BLOCKED / runtime NO_GO。** 実口座情報の取得・画面操作・MT4起動・ログイン・EA/EX4操作・発注・決済は行わない。

## 1. 比較対象の2件の証言

| 証言ID | 証拠区分 | 本人が報告した内容 | 明らかでないこと |
|---|---|---|---|
| EV-OLD | PRIOR_USER_VISUAL_REPORT | 以前の楽天MT4デモAでMACD Sampleがチャートとナビゲータにあり、**保有ポジションまたは予約注文があった**。AutoTradingはOFF_LIKE、接続表示はCONNECTED_LIKEだった | 現在も同じ状態か、実際のEA稼働状態、建玉と予約注文の内訳 |
| EV-NEW | LATEST_USER_REPORTED | 既存の楽天口座は契約中だが利用しておらず休眠状態、保有ポジション等はないとの最新申告 | 旧デモAと同一口座か、口座種別、サーバー、確認日時・確認方法、未約定注文を個別に確認したか |

どちらも本人の申告・目視記録であり、ブローカーにより現在時点の口座情報を証明したものではない。**新しい申告をもって古い記録を誤りと決めつけない。** 同じ口座でも時間経過で状態が変わること、別の口座を指していること、ポジションと未約定注文が混同されていることは「考えられる説明」であって確認結果ではない。

## 2. 照合軸と判定

| 照合軸 | 必要となる将来の非機密な証拠 | 現在 |
|---|---|---|
| 対象サービス | 楽天通常FX、楽天MT4 FXデモ、楽天MT4 FX本番などを明確に区別した製品種別 | UNKNOWN |
| 口座の同一性 | 個人情報を含めないローカルな口座ラベルの対応表と、独立した確認方法 | NOT_RECONCILED |
| MT4端末の同一性 | 単一端末の識別と、口座切替・別端末作成がないこと | UNVERIFIED |
| 接続サーバー種別 | Demo/Liveの区別。表示だけで本番でないと断定しない | UNVERIFIED |
| 時点 | 証言日時・観測日時・タイムゾーンの区別。未記録ならnull | INCOMPLETE |
| EA/スクリプト状態 | チャートへの装着、ナビゲータ内の存在、実行状態を別々に記録 | UNVERIFIED |
| 接続・AutoTrading | CONNECTED_LIKEやOFF_LIKEは外観の印象であって安全認証ではない | UNVERIFIED |
| 保有ポジション | 未決済の保有建玉の有無（PRESENT/ABSENT/UNKNOWN） | UNKNOWN |
| 未約定注文 | 指値・逆指値等の残存の有無（PRESENT/ABSENT/UNKNOWN） | UNKNOWN |
| 記録の出典 | 本人申告/過去の本人目視/将来の個別承認済み観測を区別 | PARTIAL |

**判定原則**：口座の同一性や建玉・未約定注文の有無がUNKNOWNまたは相反する場合、取引許可に昇格しない。目視情報の欠落に対して推測でABSENTを設定しない。楽天FXデモ、楽天MT4 FXデモ、本番口座を自動的に同一視しない。

## 3. 作業段階と必要な別承認

- **V0（今回）：** 既存の報告をメモリ上・文書上で整理し、情報の粒度・不足を分類。MT4の起動・照会は行わない。
- **V1（将来、本人の明示承認が必要）：** 本人がすでに把握している情報や、既に表示されている画面の限定的な目視による非機密な記録を検討。アプリを開く、画面を切り替える、ログインする行為はV1に自動的に含めない。
- **V2（別承認）：** 操作範囲・環境・ログの扱い・中断基準を事前定義した読み取り専用の口座状態照合。V1の成功はV2の承認にならない。
- **V3/V4（別承認、現時点NO_GO）：** EA/EX4の起動、注文、決済、復帰、実売買。いずれも今回対象外。

V1以降でデモ/本番が不明、既存のEAに予期しない注文経路がある、口座照合にログイン切替や既存EA変更が必要、現在の状態が確認できない場合は**新たな操作を中止**し、実環境に変更を加えず人間レビューを求める。既存注文を勝手に取り消す、EAを削除するなどの「復旧操作」は行わない。

## 4. 証拠受入基準

1. 出典の種類と時間を分離する。日時が不明な過去報告に今の時刻を付与しない。
2. 対象口座ラベルは非機密の識別子のみ。**ログインID、口座番号、パスワード、個人情報、未加工の注文履歴・残高/ポジション明細はGitHubに保管しない**。
3. 「保有ポジションがゼロ」と「未約定注文がゼロ」は別々の主張として検査。片方だけの情報から両方をゼロにしない。
4. MACD Sampleのナビゲータ内存在、チャート装着、AutoTrading表示、EA実際の稼働を別々に扱う。
5. 不一致が解消したとしてもG1の4ペア×5項目の実測値を変更しない。これは独立した検証対象。
6. 口座確認の成功は注文明細や注文権限の確認とは別。**read-onlyの証拠は実取引承認ではない**。

## 5. 停止条件と監査記録

- `account_identity_consistency=NOT_RECONCILED`、`positions_status=UNKNOWN`、`pending_orders_status=UNKNOWN`の間は現場運用へ進めない。
- 将来の確認で一致が示されても、時間経過、別口座、過去の自動EA取引などが原因だと証拠なしに断定しない。
- 照合時に新規口座開設・複数環境構築・楽天への問い合わせは行わない（本人決定）。
- 本文書のチェックリストとJSONは監査**設計**であり、実機で得た新しい証拠は含めない。
