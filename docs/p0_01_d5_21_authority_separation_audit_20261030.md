# P0-01 D5-21：停止・証拠・承認権限の分離監査

監査日：2026-10-30。対象：D5-18（証拠）、D5-19/20（合成停止・復元・証拠統合）、新規D5-21（権限境界）、D5-12の残存G1〜G9。**OFFLINE_SYNTHETIC_ONLY。実機・口座照会・EA/EX4実行・売買は行わない。**

## 1. 独立した3軸

| 軸 | オフラインで言えること | オフラインでは言えないこと |
|---|---|---|
| 証拠 | D5-17のEV-OLD/EV-NEWを未照合として保持。D5-18の合成口座識別・矛盾・時刻の整合条件を検査 | 既存楽天口座が旧デモAと同一か、最新建玉・未約定注文やEAの実際の稼働 |
| 停止 | D5-7〜10とD5-19/20の合成ラッチ・復元・旧日付・時刻不一致を検査 | 停止履歴の実永続化、外部真正性、MT4発注停止の強制力、起動後の停止継続 |
| 本人承認 | D5-21で仮想の承認申告を**すべて非認証・非権限**と判定。EA実行、注文、停止解除、実運用を別々の操作と区別 | 本人確認、改ざん耐性のある承認記録、特定の端末/口座/目的/期限に限定した実行権限、承認取消し |

この3軸は**AND条件であって、1軸の良好判定が他軸の不備を補わない**。合成証拠・停止履歴が全て整合しても、後続の実行承認を作らない。

## 2. D5-21のAPIと承認の扱い

- `scripts/p0_01_d5_21_authority_audit.py`の `audit_offline_authority_separation(integrated_fixture, approval_claim)` はD5-19/20統合判定を**内部で再計算**し、外部から渡された「正常」との要約値を信用しない。
- `approval_claim` は厳密な`origin=SYNTHETIC_ONLY`、`schema_version=1`、`requested_action`、`claimed_human_approval`、`claimed_safety_review_passed`、`claimed_stop_release`、`approval_reference`の7フィールド。bool以外は拒否し、余剰キーや欠落も拒否。
- 対象操作は`VISUAL_REVIEW`、`MT4_LAUNCH`、`ACCOUNT_LOGIN`、`READ_ONLY_QUERY`、`EA_EXECUTION`、`ORDER_ACTION`、`STOP_RELEASE`、`LIVE_TRADING`。いずれも今回**未承認**。
- `claimed_human_approval=true`や`SYNTHETIC_APPROVAL_...`の記載は、**入力に含まれる未検証の主張**であって認証された本人の同意ではない。`approval_reference`は疑似テスト用で、本物の承認番号として流用禁止。
- 有効な本人承認を登録・照合・行使する仕組みはD5-21には**存在しない**。したがって「承認申告の形式が正しい」だけで注文やEA起動を許す経路も存在しない。GitHub PRのマージやCI成功は本人の実機操作承認ではない。
- 入力に実口座番号、認証情報、残高・注文明細、実在する承認識別情報を保存しない。結果にも承認申告文字列を反映しない。

### 代表的な判定と優先順位

| 条件 | 返却status | 取引権限 |
|---|---|---|
| 承認申告の不正、子ゲートの拒否契約違反 | `AUTHORITY_INPUT_REJECTED_FAIL_CLOSED` | なし |
| 証拠未照合、停止ラッチあり、旧時点/口座不一致、証拠または停止が異常 | `EVIDENCE_OR_STOP_BLOCKED_NO_GO` | なし |
| 合成条件が整合したが停止解除を要求・主張 | `STOP_RELEASE_CLAIM_DENIED_NO_GO` | なし |

| 合成条件が整合したが承認の主張もない | `EXPLICIT_APPROVAL_NOT_PRESENT_NO_GO` | なし |

**すべての返却**：`approval_verified=false`、`action_authorized=false`、`ea_execution_authorized=false`、`order_authorized=false`、`stop_release_authorized=false`、`effective_approved_actions=[]`、`safety_hold_latched=true`、`runtime_go_no_go=NO_GO`、`verified_values=null`、`broker_verified=false`、`production_usable=false`、`read_only_ex4_execution_approved=false`、`terminal_execution_approved=false`、`orders_generated=false`、`forward_trading_enabled=false`、`phase_1=BLOCKED`。

### 合成回帰の受入基準

- 新規35テストで全操作の権限分離、捏造承認、偽の安全レビュー/停止解除、口座・EA・建玉情報不足、日次停止、DD5%、履歴異常、時刻・口座の不整合、無効スキーマを横断確認。
- 子ゲートが`GO`を返す・安全ホールドを解除するなどの**想定外の返値**を模擬し、結合先が拒否することを確認。
- 入力は不変、同じ関数を連続呼出ししても承認や停止状態が残存しない設計。これは**真正な停止状態の永続化ではない**。
