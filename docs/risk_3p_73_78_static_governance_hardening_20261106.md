# RISK-3P-73〜78：オフライン検査の実行前境界・全レポートスキーマの強化

作成日：2026-11-06（JST）。PR #186がGitHubのmainへマージされたことを確認し、新ブランチで実装。

## 目的

これまでの安全なオフライン検証器を増やすだけでなく、**検証コードそのものが不審な式を評価しないこと、および検証結果が新しい偽承認項目を含んだまま合格扱いされないこと**を強化する。新しい実MT4観測、口座データ収集、プライベートログ読込、EA・注文操作は行わない。

| 工程 | 対象 | 追加する制限 |
|---|---|---|
| RISK-3P-73 | `scripts/audit_risk_3p_69_import_time_safety.py` | 選定6つの純粋合成モジュールについて、トップレベル代入の値や関数デフォルト値をリテラルに限定。名前解決、属性参照、添字演算、数式、文字列書式化、内包表記、lambda等による読み込み時の動的評価を拒否。注釈内の関数呼出も拒否 |
| RISK-3P-74 | `scripts/audit_risk_3p_56_static_offline_boundary.py` | `__globals__`、`__dict__`、`__subclasses__`など、Pythonの内部オブジェクトへ迂回できる属性参照を選定6モジュールのAST監査で拒否 |
| RISK-3P-75 | `scripts/risk_3p_71_offline_integrity_gate.py` | 7つの合成サブレポートの**全フィールド名・値・型**を静的期待値と厳密照合。既知の危険フラグだけでなく、新規未知フィールド・欠落フィールド・bool/int混同も拒否 |

| RISK-3P-77 | 同上・既存の静的監査テスト | 合法的な固定文字列・定数・構造体、既存6モジュールのPASSを維持。唯一の例外として、合成ハッシュ鎖の**既定の正確なHEX64正規表現**だけを許す |
| RISK-3P-78 | PR・CI・設計文書 | 新しいソース登録は増やさず、既存45件の固定インベントリを維持したまま全テストとWindows CIで回帰を確認 |

## 効果と限界

- import時のAST検査は**Pythonの静的構文の限定レビュー**であり、第三者ライブラリ内部、ネイティブコード、実行時の動的挙動や暗黙のクラス機構の完全な形式証明ではない。
- 7つのレポートの厳密スキーマ化は、**本工程で決めた合成検査結果の不審な変化を検出**することを目的とする。将来レポート形式を正当に変更する場合、期待値のレビュー更新が必要。
- 固定ソース名45件の対照台帳は変更なし。本人の明示的な安全承認、実証値・証拠参照、口座同一性、サーバー注文の照合は未完了。
- 既存のリスク上限：1取引0.5%、同時合計1.0%、日次1.5%、DD4%新規停止、DD5%全決済・本人承認。通信障害・単調時計・NY17:00基準も不変更。
- **P05 0/8 BLOCKED、G1 0/15、FX-SAF原議0/15、FORM承認0/43、PHASE-1 BLOCKED、runtime NO_GO、safety_hold_latched=true、verified_values=null。**
- 楽天MT4・MACD Sample・建玉・未約定注文・注文履歴・実口座情報へアクセスしていない。

方式Eを継続し、承認不要のオフライン修正をまとめて実施するが、**mainへのマージ・実MT4観測・発注・停止解除は実行しない**。
