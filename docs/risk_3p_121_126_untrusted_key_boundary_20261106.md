# RISK-3P-121〜126：合成リスク引継ぎにおける辞書キーの安全境界

作成日：2026-11-06 JST。PR #195がmainにマージ済みであることをGitHubで確認し、新規ブランチで実装。

## 修正した問題

架空の損切り計算からポートフォリオ計算への引継ぎ照合 `review_synthetic_loss_handoff` では、架空契約情報・3ペア価格のキー集合を`set(contracts)`等で検査していた。

Pythonの組込み`dict`は、**文字列以外のオブジェクトをキーに保持できる**。キーを`set`へ変換すると、キー自身の`__hash__`または`__eq__`が呼び出され得る。前工程で値（dataclass）の型やレポート内容を検査しても、キーそのものの検査より前に不審な処理が走る余地があった。

## 工程

| 工程 | 改善 |
|---|---|
| RISK-3P-121 | 組込みdictに限定した`_mock_plain_three_pair_map`を追加。キーの**exact typeが組込みstrであること**を先に検査してから3ペアの集合を比較する |
| RISK-3P-122 | strサブクラスと独自オブジェクトの悪意ある`__hash__`・`__eq__`が、照合関数で実行されないことを架空入力で検査 |
| RISK-3P-123 | `dict`サブクラスの異常な反復処理、リスト/タプル等の非dict入力を、反復・比較前に拒否 |
| RISK-3P-124 | 必須の3ペアUSD/JPY・EUR/JPY・EUR/USDの欠落／追加／未知キー、bool/int/bytes/tuple/Noneキーを拒否 |
| RISK-3P-125 | 従来どおり正常な3ペア合成引継ぎは通過し、未知の照合状態、偽承認、価格時刻の不一致、損失申告改変をFail Closed |
| RISK-3P-126 | 新規26回帰テスト、Q109の既存ソースへの紐付け、厳格な移行監査の更新、PR/CI |

## 効果と限界

今回の改善は、**既にメモリ上にある架空辞書のキーを、ハッシュや等価比較前に型確認する**という狭い保護である。悪意あるキーを辞書へ**挿入する瞬間**のハッシュ処理、任意Pythonオブジェクトに対する完全なサンドボックス隔離、外部データの真正性まで保証するものではない。

新しい成功値は付与しない。元の`mock_binding_consistent=True`も架空の内部整合性を示すだけであり、実ブローカー証拠、本番ストップや約定の安全性、注文承認を意味しない。生成される結果は必ず`NO_GO`・`BLOCKED`・停止ラッチtrueとし、停止解除や注文操作は許可しない。

従来の45本の固定オフラインソース、合成対象3ペア、0.5%／1.0%／日次1.5%・DD4%/5%などのリスクルールは不変更。

**P05 0/8 BLOCKED、G1実値0/15、FX-SAF原議0/15、FORM承認0/43、PHASE-1 BLOCKED、runtime NO_GO、safety_hold_latched=true、verified_values=null**を維持。

実MT4、EA、建玉・未約定注文、証券会社、個人のWindowsログ・認証情報にはアクセスしない。方式Eの指示に従いPRとCIまでの承認不要オフライン作業は続けるが、mainへのマージ・本番売買許可は人間の判断に残す。
