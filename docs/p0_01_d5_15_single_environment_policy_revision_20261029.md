# P0-01 D5-15 方針変更記録：単一口座・単一MT4環境

決定日：2026-10-29。本人の最新指示を優先。旧D5-13〜D5-15の「独立デモBを追加」「楽天へ問い合わせ」の進行案を**撤回**する。旧文書は履歴として参照できるが、以降の有効な運用指示ではない。

## 1. 正式採用方針

1. 楽天証券へメール等の問い合わせを行わない。問い合わせ文案は**CANCELLED / DO_NOT_SEND**。自動送信・代理送信も行わない。
2. テスト期間を含め、複数の異なるデモ口座や複数のMT4運用環境を設けない。**単一環境で開発・検証する**（ただし現在の実環境操作は未承認）。
3. 楽天の既存口座は契約中だが休眠状態で、現状は保有ポジション等がないとの本人最新報告を記録する。これは**申告**であり、MT4/ブローカーからの取得・照合による実測証拠ではない。
4. 以前の目視報告では既存デモ環境AにMACD Sampleおよび保有/予約注文があった。今回の「口座は利用しておらずポジションなし」が同じ口座と同じ時点を指すか未特定であるため、旧報告を黙って消さず、**口座同一性と現在の状態はUNVERIFIED**とする。実環境での操作前に、対象口座種別と誤操作リスクを別承認による目視確認の計画で解消する。今はログイン・MT4起動・EA切替・注文変更・口座照会を実施しない。
5. 口座Bの新規開設、同時ログイン、別VM/専用Windowsユーザー、独立MT4インストール、口座A/Bの並行運用は**現行スコープ外**。実行せず、このための承認要求も行わない。

## 2. 楽天の公開文書の適用範囲を区別する

- 楽天FXデモのFAQには「デモ口座は利用者1人につき1口座」と記載：
  https://rfx.rakuten-sec.co.jp/demo/faq/
- 楽天MT4デモの案内には「デモ口座は何度でも作成することができます」と記載：
  https://www.rakuten-sec.co.jp/web/fx/mt4/demo-account.html
- 上記の文書だけで「楽天MT4 FXデモは技術的に複数IDを同時保持できない」と断定しない。制度・実装上のE1〜E3は**未実証であり、しかし今後の構成選択には不要**。追加調査・問い合わせのために進行を止めるのではなく、追加環境を作らない方針で依存関係を取り除く。
- 一般の楽天FXデモ、楽天MT4 FXデモ、本番MT4、MT4 CFDデモを混同しない。

## 4. 単一環境での今後の安全な開発順序

- 現在：既存のオフライン合成モック、仕様とPythonテストを継続する。実口座やMT4にはアクセスしない。
- 次の机上工程：単一環境を用いた*将来の*目視レビュー項目、対象口座の識別、EA/AutoTrading/ポジション残高の状態を誤認しないチェックリストを作る。これは操作承認ではない。
- 将来実環境へ移る場合：ユーザーが操作を個別に明示承認した時だけ、対象口座（デモ/本番）の区別、既存EAの有無、建玉・予約注文の有無、注文機能が無効であることを段階的に確認する。異常・不明は止める。
- 読取り承認が与えられたとしても、EA/EX4起動、注文、決済、実売買を自動的に許可しない。各段階を別個に扱う。
