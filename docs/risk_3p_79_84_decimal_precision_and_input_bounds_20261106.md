# RISK-3P-79〜84：3ペア合成リスク計算の端数・負荷・入力境界の安全化

作成日：2026-11-06 JST。PR #187のmainへのマージ（GitHub確認済み）を起点に新ブランチで実装。

## 修正理由

`scripts/phase1_three_pair_synthetic_risk.py` は、入力された`max_loss_jpy`を計算し、口座純資産の0.5%（新規候補）、1.0%（合計）の上限と比較する**架空の非運用計算器**である。旧実装は `decimal.Decimal` のコンテキスト既定有効桁数28で金額を足し合わせていた。このため、`500.00000000000000000000000000000000001`など**500円をわずかに上回る値**を最初の加算時に500円へ丸めてしまい、上限超過を`False`とする可能性があった。実取引システムに接続されていなくても、リスク検証例としては危険な誤りである。

## 重要な区別

このコードに与えられる`max_loss_jpy`は**呼出側が仮に主張した金額**であって、ブローカー情報・ストップロスの実効性・スリッページ・ギャップ・約定・相場急変を根拠に検証した最大損失ではない。計算が完了して0.5%/1.0%以内と表示されても、**取引可とはならず、必ず`NO_GO`／`BLOCKED`／停止ラッチtrue**を返す。

128件・128文字・時刻整数の上限は、**非運用デモ計算のリソース制限**であり、運用上の取引件数・取引時間・実ブローカーの最大注文量を定義するものではない。運用上の詳細は別途安全審査・本人承認が必要。

NY17:00の日次区切り、日次損失1.5%、DD4%/5%、通信断、時計異常、手動停止解除、単一デモ口座、MT4のMACD Sampleについての既存条件は変更しない。

**P05 0/8 BLOCKED、G1実15項目0/15、FX-SAF原議0/15、FORM承認0/43、PHASE-1 BLOCKED、runtime NO_GO、safety_hold_latched=true、verified_values=null**を維持する。
