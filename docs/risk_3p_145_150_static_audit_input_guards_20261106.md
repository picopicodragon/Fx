# RISK-3P-145〜150：静的監査の不審な辞書キー・注釈評価・巨大入力を拒否

作成日：2026-11-06 JST。PR #198のmainマージから独立したブランチで実装。PR #199とは変更ファイルの重複がないため、どちらもmainへ自動マージせず独立レビュー可能。

## 発見した問題

既存の`audit_risk_3p_56_static_offline_boundary.py`と`audit_risk_3p_69_import_time_safety.py`は、6つの純合成バリデータのリポジトリ公開PythonソースをAST解析する限定的監査器である。

しかし、`audit(..., overrides=...)`の辞書キーは組込みstrに限らず任意のPythonオブジェクトである。従来のP56は未知キーかを型確認前に`key not in TARGETS`で比較し、P69は`set(overrides)`でハッシュ化していたため、既存のオーバーライド辞書に混入した不審キーの`__hash__`/`__eq__`を呼び出す余地があった。

また、P69は関数・モジュールのアノテーションに含まれる`ast.Call`等を検査していたが、**`from __future__ import annotations`を削除した場合**、関数定義時に属性参照・添字参照などの注釈式が実際に評価され得ることを確認していなかった。今回の固定6モジュールはすべて将来注釈を使っている。無関係な巨大AST入力も過負荷要因になるため、テスト専用の文字数制限を追加した。

## 工程

| 工程 | 対応 |
|---|---|
| RISK-3P-145 | P56の`overrides`が組込みdict・組込みstrの許可済みキー・組込みstrの値から構成されるか、比較前に検査。不正入力は固定コードで直ちに拒否 |
| RISK-3P-146 | P69の`set(overrides)`を除去し、同様に型確認を先行。拒否時にオーバーライドや公開ソースを処理しない |
| RISK-3P-147 | P69で、将来注釈を有効化していない関数・モジュール変数の注釈を`P69_UNPOSTPONED_ANNOTATION_EVALUATION`として拒否 |
| RISK-3P-148 | P56/P69のAST元文字列、オーバーライドの最大長を64Ki文字に制限。大きすぎる入力はソースを解析・反映せず固定コードで拒否 |
| RISK-3P-149 | 過去に許可した実際の6つの純合成ソースが引き続きPASSとなり、監査が`NO_GO`・本番未承認を保持することを回帰検査 |
| RISK-3P-150 | 既存の2テストファイルへ18件を追加し、独立したPR/Windows/Repository CIで検証 |

## 対策の限界と安全状態

これは**限定的な6ファイルの静的AST検査器の入力検証**であり、任意Python実行環境のサンドボックス、依存モジュール全体の無害性、Broker APIの真正性、注文制御の安全性を証明しない。Python辞書への悪意あるキーを**挿入する瞬間**の処理も防止できない。

ソース文字数64Ki制限は今回の監査を過大入力から保護するための制限であり、本番FX入力件数やファイルサイズの規格ではない。固定6ソース、45件の全非運用Q109ソース台帳、`production_authorized=false`を維持する。

**P05 0/8 BLOCKED、G1実証0/15、FX-SAF原議0/15、FORM 0/43、PHASE-1 BLOCKED、runtime NO_GO、safety_hold_latched=true、verified_values=null**を維持。0.5%／1.0%／日次1.5%、DD4/5%停止、NY17:00等の運用安全規則も変更しない。

この変更で実MT4、EA、楽天証券、建玉、未約定注文、秘密のローカルログにアクセスしたり、発注・停止解除・mainマージを行ったりしない。
