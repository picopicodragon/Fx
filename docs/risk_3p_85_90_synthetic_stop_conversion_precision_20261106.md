# RISK-3P-85〜90：合成損切り額・JPY換算の高精度化と検証強化

2026-11-06 JST。PR #188のmainマージ確認後、新ブランチで実施。

## 課題

`scripts/phase1_three_pair_synthetic_stop_conversion.py` の架空の損切り額・JPY換算の計算では、従来 `localcontext(prec=48)` だった。1つのチケットでストップ幅×ロットあたり基準数量×ロット数×JPY換算レートの4要素を掛け合わせる場合、入力がそれぞれ最大18有効桁であることを考えると48桁では**有効な微小追加費用が丸め落とされる可能性**がある。実口座の損失を保証する算式ではないが、模擬検査の計算正確性に関わる。

さらに旧`_parse`の`number.normalize()`は呼出側のDecimalコンテキスト精度に影響されるため、19桁以上の数値が丸められて18桁以内と誤分類されることがある。入力の検証自体も実行環境のDecimal設定から独立させる。
