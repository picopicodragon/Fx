# RISK-3P-109〜114：合成FXエクスポージャーの三重積と微小端数の厳密計算

作成日：2026-11-06 JST。PR #192のmainマージをGitHubで確認し、新ブランチで実施。

## 検出した具体的な数値欠陥

前工程までに、合成リスク計算の`Decimal`精度を96桁に設定したが、**`phase1_three_pair_synthetic_risk.py`の通貨エクスポージャーは最大3つの40桁数字の積**を計算するため、96桁では足りない。

EUR/USDの数量40桁 × EUR/USDレート40桁 → USD側通貨脚80桁。これをUSD/JPYの40桁レートで架空JPY換算すると**120桁**に達する。旧96桁では四捨五入が起きる。大きな数量と極小数量が同一の合成ポートフォリオに混在する場合、末尾に加算される微小端数も失われ得る。

これは**架空の通貨脚総額と換算総額の算術正確性**に関する不具合であり、実口座の実損失上限の逸脱を確認したものではない。

| 工程 | 対応内容 |

| RISK-3P-109 | 3ペア合成ポートフォリオの計算精度を96桁から**256桁**に引き上げ。外部Decimalコンテキストからの独立性は維持 |

| RISK-3P-114 | テスト23件、既存精度依存テストの更新、Q109と厳格な移行監査、設計文書、PR/CI |

## なぜ256桁か

合成ポートフォリオの数値入力は1つ最大40文字の正規化10進文字列、同時取引は最大128件。USD/JPYの3因子総額は、最大おおむね120桁の整数部分と、最低約114桁の小数部分が同時に含まれ得る。128件分の繰上がり数桁を加えても、**256桁で保持できる**という保守的な算術上限を採用する。

別の合成損切り額モジュール`phase1_three_pair_synthetic_stop_conversion.py`では、正値入力が最大18有効桁、1e12以下に制限されているため、**既存96桁を維持する**。両モジュールの精度を同一とする旧テストの前提を修正し、意図した差を明示的に検査する。

**本実装は「合成数値の桁落ち防止」であり、本番ロット／証拠金／実際の換算額を検証するものではない。** 特に通貨脚のグロスJPY換算は、ブローカーの実際の損失リスク・約定損失・清算額と同義ではない。
